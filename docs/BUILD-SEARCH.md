# 장비 세팅 검색

고정 무기를 지정하고 목표 스킬을 하나 이상 선택하면 방어구 다섯 부위, 호석, 장식주 배치를 검색한다. 일반 스킬과 세트·그룹 효과를 목표로 지정할 수 있다. 전체 커뮤니티 규칙 및 제작 호석 / 보유 호석만 / 호석 없음 모드를 지원한다. 보유 모드는 입력된 보유 데이터를 사용하며 게임 생성 가능성을 재보증하지 않는다.

## 데이터 근거

- 한국어 장비 데이터: [MHDB API](https://wilds.mhdb.io/ko/armor), [API 문서](https://docs.wilds.mhdb.io/), [데이터 프로젝트](https://github.com/LartTyler/mhdb-wilds).
- 스냅샷의 API 반영 버전: **2026-04-15T01:28:18+00:00**. 이는 API의 캐시 갱신 확인용 버전이며 Capcom 게임 버전이 아니다. 최신 게임과의 일치는 미확인이다.
- 스킬 177개, 방어구 714개, 선택 무기 411개(제작 최종 단계 355개 + 아티어 기본 구성 56개), 장식주 361개. 제작 무기는 다음 강화 경로가 없는 마지막 단계만 선택한다. 아티어는 API의 파생 정보 없는 항목을 기본 구성으로 포함하고, 스킬·슬롯·방어력 구성이 같은 변형은 하나로 표시한다. 공격력·속성·예리도 차이는 이 검색의 계산 대상이 아니다.
- `scripts/export_equipment_snapshot.py`가 한국어 이름·레벨·슬롯·최대 방어력·세트 문턱을 정규화한다. 전후 API 버전이 같아야 내보내며 원본 응답 SHA256과 URL을 함께 저장한다. 원본 코드·이미지·설명 문구는 복제하지 않았다.
- 호석 규칙 근거와 공식 검증 한계는 [TALISMAN-RULE-AUDIT.md](TALISMAN-RULE-AUDIT.md) 참조. 장비 데이터에 없는 스킬(예: 가드 성능 Up) 또는 최대 레벨을 넘는 호석 후보는 제외한다.

## 검색과 검증

상위 방어구만 검색한다. 목표 기여도, 종류별 슬롯 수·크기, 방어력과 지정한 속성 내성에서 다른 장비보다 불리한 장비를 제거하여 대표 후보를 구성한다. 같은 목표·슬롯 구성을 가진 호석을 합치고, 같은 구성의 보유 호석을 우선 대표로 선택한다. 목표에 포함되지 않은 스킬이나 외형이 다른 모든 장비를 나열하지 않는다.

방어구 조합을 탐색하고 부족한 목표는 장식주 재귀 검색으로 채운다. 복합 장식주의 모든 스킬을 함께 더하며 무기/방어구 슬롯과 크기를 별도로 지킨다. 세트 효과는 각 부위의 소속을 한 번씩 세어 필요 부위 수에 따라 발동한다. 출력 전 실제 장식주 위치와 목표 충족을 다시 확인한다.

최대 20개 대표 결과, 60초 또는 2,000,000회 탐색 제한에서 중단한다. 제한에 도달하면 부분 결과라고 표시한다. 결과 0개도 중단 상태에서는 불가능 판정이 아니다. 워커를 종료하여 취소하고, 조건·보유 데이터 변경이나 화면 닫기 시 이전 작업을 무효화한다.

## 현재 범위

장식주는 수량 무제한, 방어력은 최대 강화 기준이다. 세팅 저장은 SAVED-BUILDS.md의 독립 스냅샷으로 지원한다. 무기 공격력 최적화, 아티어 복원 보너스 수치, 장식주 보유 수량, 제작 재료 보유 여부는 미지원이다. 세팅 검색이 공식 게임 전체 경우를 완전히 검증했다는 뜻은 아니다. Windows 실기기 검증은 별도 필요하다.

단위 테스트는 복합 장식주, 슬롯 종류·크기·재사용 금지, 세트 문턱, 최소 방어력, 보유 호석, 후보 축소와 제한 상태, 스냅샷 참조를 확인한다. 실제 Chromium에서 전체 규칙/호석 없음 검색, 취소, 조건 변경, 키보드 초점 복귀, 320·768·1440px 화면을 확인했다.

## 무기 목록 필터 검증

API의 crafting.branches와 자식 항목의 crafting.previous를 함께 확인해 제작 무기의 최종 단계를 선택한다. 분기별 마지막 무기와 후속 강화 없는 독립 제작 무기는 유지한다. 아티어 중복 변형의 원본 ID는 sourceIds에 보존한다. Python 테스트로 분기·자식 참조·동일 구성 합치기를 확인하고, 실제 브라우저에서 14개 무기 종류의 목록과 제작/아티어 검색을 확인했다. 최종 단계는 스냅샷의 강화 경로 기준이며 미래 업데이트의 단계까지 의미하지 않는다.

## 스킬 분류와 거극 아티어 부여 스킬

참고한 시뮬레이터: https://mhwilds.wiki-db.com/sim/ . 공개 한국어 데이터/검색 코드의 버전 20260917T022420에서 스킬 분류와 무기 시리즈·그룹 각각 1부위 합산 구조를 확인했다. 원본 코드나 화면 자산은 복제하지 않았다. 스킬 분류 이름과 소속을 현재 MHDB ID에 대응시킨 데이터는 `prototype/data/skill-categories.json`에 출처 URL과 버전을 기록했다.

전체 스킬 메뉴에서 무기·전투(공격/속성/생존)·내성·파라미터·아이템·퀘스트·시리즈·그룹 분류별 목록을 보고 각 스킬 옆의 레벨·효과를 선택한다. 이름뿐 아니라 효과명(근성, 선전호응 등)으로도 즉시 필터한다. 참고 목록에 없는 MHDB 스킬은 weapon/set/group 종류를 따르며 남은 일반 스킬은 기타 방어구 분류로 표시한다. 현재 검색 대상 177개를 중복 없이 포함한다. 분류와 검색은 목록 표시만 바꾸며 선택한 목표를 보존한다. 선택 요약에서 개별 목표를 해제하거나 전체 해제할 수 있다.

거극 아티어 14개에서 시리즈 1개·그룹 1개를 선택한다. 지정 안 함도 지원한다. 검색 엔진은 각각 1부위로 목표 계산과 발동 효과에 합산하고 최종 결과를 실제 합계로 검증한다. 제작/일반 아티어에서는 입력값을 지우고 비활성화하며 엔진도 부여 요청을 거부한다. 실제 무기에 붙은 스킬을 수동 지정하는 기능이며, 모든 표시 스킬의 무작위 부여 가능성을 보증하지 않는다. 복원 공격력 등 수치는 미반영이다.

검색 결과의 무기 부여 스킬과 발동 효과를 저장·비교·백업에 보존한다. 이전 저장 세팅의 부여 정보가 없으면 없음으로 읽는다. 저장 당시 스냅샷을 현재 무기 설정으로 덮어쓰지 않는다.

사용자 요청에 따라 페이지 상단의 거극 입력/스킬 분류 바로가기 버튼을 제거했다. 거극 부여 영역은 항상 표시하고 해당 무기에서만 선택을 활성화한다.

목표 개수의 임의 상한을 제거했다. 각 스킬은 한 번만 선택할 수 있고 지원 데이터에 존재하는 스킬·레벨인지 검증한다. 최소 한 개 목표가 필요하다. 검색 시간·탐색량·결과 제한은 그대로 적용한다. 저장과 백업 복원에도 8개 제한은 없다.

## 요청에 따른 검색 제외

2026-10-07 권의 극에 달한 자(ID157)와 주먹밥(ID158)을 검색 데이터와 스킬 분류에서 제외했다. 권의 극에 달한 자는 MHDB의 귀신 협업 방어구 5개에 연결되어 있어 다른 시리즈 데이터 혼입과 구분한다. 주먹밥은 현재 스냅샷에서 장비/장식주 연결이 확인되지 않았다. 사용자 요청에 따른 제외 정책이며 두 항목 모두 게임에 없는 스킬이라는 판정은 아니다. 내보내기 스크립트와 excludedSkills 메타데이터에도 반영해 재생성 시 유지한다. 기존 저장 세팅은 과거 스냅샷으로 보존한다.

## 제작 무기 스킬 자동 선택

제작 무기를 선택하면 그 무기의 모든 기본 스킬을 실제 레벨로 목표 메뉴에 자동 반영한다. 자동 목표는 무기 변경 시 갱신하고 수동 목표는 별도로 보존한다. 같은 스킬의 수동 목표가 더 높으면 그 레벨 하나를 사용한다. 기본 스킬 이하로 해제할 수 없으며 직접 목표 해제 버튼은 수동 선택만 지운다. 이는 목표 표시/입력의 자동화이고 엔진이 이미 계산하는 무기 스킬을 추가로 더하지 않는다. 생성 결과의 목표와 전체 스킬 총합은 저장·비교·백업에 기존 방식으로 남는다.

## 간결한 수동 메뉴

일반 스킬은 작은 가로 레벨 선택 칸을 사용한다. 현재 스냅샷에서 방어구/장식주 연결이 없는 무기 스킬 15개는 weaponOnlySkillIds로 기록하고 수동 메뉴에서 숨긴다. 전체 스킬 데이터와 무기 효과는 유지한다. 자동 목표는 DOM 선택 칸의 유무와 독립적으로 무기의 모든 기본 스킬을 포함해 검색·저장한다. 이는 현재 데이터에 따른 메뉴 분리이며 해당 스킬 자체를 게임에서 제거한다는 뜻은 아니다. 수동 목록은 162개, 데이터 전체는 177개다.

## 상위 전용 및 속성 내성 조건

방어구 등급 선택을 제거하고 상위만 검색한다. 불·물·번개·얼음·용의 최소 내성을 각각 -25~+25 정수로 지정하며 드롭다운의 제한 없음은 내성 조건을 적용하지 않는다. MHDB armor의 resistances를 다섯 방어구에서 합산한다. 스킬·식사 효과를 포함한 최종 게임 내성이 아닌 기본 방어구 합계다. 지정된 내성은 후보 축소, 탐색 상한, 최종 결과 검증에 반영한다. 결과와 저장·비교·백업에 다섯 기본 내성을 보존하며 이전 저장의 누락 값은 미기록으로 표시한다.

입력 영역은 넓은 고정 무기 옆에 거극 부여 스킬을 배치하고, 짧은 무기 종류·호석 범위는 좁게 유지한다. 방어력과 5속성 최소 내성은 아래 줄에 모으며 모바일에서는 줄을 나눈다.

검색 결과는 세팅 번호·무기·방어력·목표 달성 스킬의 요약 목록으로 표시한다. 각 항목을 클릭하거나 키보드 Enter/Space로 열면 기존 상세 카드(기본 내성·장비·호석·장식주·발동 효과·저장 버튼)가 펼쳐진다. 여러 항목을 동시에 열 수 있고 다시 닫아도 검색 결과는 유지한다.

선택 요약에서도 각 목표의 레벨/효과를 드롭다운으로 바꿀 수 있으며 전체 목록과 동기화한다. 제작 무기 기본 레벨보다 낮은 선택은 막고, 수동 목표를 해제해도 자동 기본 목표는 유지한다. 무기 전용 자동 스킬은 실제 무기 레벨을 고정 표시한다. 변경 시 기존 검색 결과를 무효화한다.

## 인게임 참고 상세 화면

검색 결과를 펼치면 왼쪽부터 무기·방어구, 부위별 장식주, 전체 장비 스킬·시리즈 스킬·그룹 스킬, 방어 스테이터스를 표시한다. 호석은 별도 패널로 분리하고 무기/방어구 장식주 슬롯을 각각 표시한다. 장식주 아이콘 숫자는 장착 슬롯 레벨이며 이름의 표기는 장식주 요구 레벨이다. 빈 슬롯도 유지한다.

장비 스킬은 목표만이 아닌 장비·호석·장식주 합계를 지원 최대 레벨로 제한한 목록이다. 시리즈/그룹은 무기 부여와 방어구 기여 부위, 현재 발동한 스킬과 최고 단계 효과만 표시한다. 미발동 스킬과 낮은 단계 효과는 숨긴다. 방어력/내성의 기존 계산 범위와 저장 형식은 유지한다.

사용자 제공 게임 화면을 참고한 자체 SVG로 14종 무기·5종 방어구·호석·장식주 슬롯 및 내성 아이콘을 구현했다. 게임 원본 아이콘 파일을 추출한 것은 아니며 색상은 UI 구분용이다. 캐릭터·공격력·체력·스태미나는 표시하지 않는다. 작은 화면에서는 패널을 순서대로 배치하되 장비와 해당 장식주는 나란히 유지한다.

검색 상세의 무기·방어구에는 데이터의 RARE를 표시한다. 각 장비의 기본 스킬을 펼치면 장식주·호석 합산 전의 스킬 레벨과 시리즈/그룹 기여(1부위)를 볼 수 있다. 호석 TXT에는 원본 레어도가 없어 검색에 사용한 생성 규칙의 레어도 후보를 규칙 기준으로 표시한다. 여러 규칙이 맞으면 후보를 함께 표시하고 일치 규칙이 없으면 미확인으로 둔다.

## 검색 조건 유지

무기 종류·고정 무기·거극 부여 스킬·호석 범위·최소 방어력·5종 최소 내성·직접 선택한 목표·스킬 검색어와 분류를 `mhwilds-build-inputs-v1`에 자동 저장한다. 새로고침하거나 다시 방문하면 데이터 로드 후 복원하고 제작 무기 자동 스킬을 다시 적용한다. ‘검색 조건 초기화’는 검색을 중단하고 조건을 기본값으로 되돌려 저장한다. ‘직접 선택한 목표 해제’는 수동 목표만 해제한다.

검색 결과 자체는 저장하지 않으며 복원 후 검색 버튼으로 다시 계산한다. 이 입력 상태는 호석/저장 세팅 백업과 별개이며, 브라우저 사이트 데이터 삭제 시 함께 사라진다. 저장 공간 또는 브라우저 정책 때문에 자동 저장할 수 없으면 화면에 안내한다.

## 제작 호석 및 직접 세팅 (2026-10-13)

전체 규칙 모드에 MHDB `/ko/charms`의 고정 호석 182개 강화 단계를 추가했다. 랜덤 호석 4종은 이 목록에 포함하지 않으며 기존 커뮤니티 규칙을 사용한다. 기존 사용자 제외 정책의 주먹밥 호석 1개는 제외한다. `craftedCharmsRetrievedAt`, 출처 URL 및 SHA-256을 스냅샷에 기록하며 기존 장비 수집 일자는 변경하지 않았다. 검색 대표 후보 축소 규칙 때문에 모든 제작 호석을 각각 나열하지는 않는다. 보유/호석 없음 모드에 미보유 제작 호석을 추가하지 않는다. 제작 호석의 이름·레어도는 상세·저장·백업에 보존한다.

`#manual` 직접 세팅 메뉴에서 기존 지원 범위의 무기, 상위 방어구 다섯 부위, 제작 또는 보유 호석과 슬롯별 장식주를 선택한다. 이름·스킬 검색, 슬롯 종류·크기 검사, 거극 부여, 합산 미리보기, 이름/보관함 지정 저장을 지원한다. 장비 교체 시 부위·종류·번호가 같고 여전히 호환되는 장식주만 유지한다. `mhwilds-manual-build-v1`에 선택 내용을 자동 저장한다. 직접 입력 선택 상태는 백업 대상이 아니며 완성 후 저장한 세팅은 기존 백업·복원·비교에 포함된다.

검증: Node 테스트 60개·Python 기존 무기 선택 테스트 3개 및 변경 JS 구문 검사 통과. Chromium에서 장비/장식주 선택, 저장/새로고침 복원, 저장 상세의 제작 호석, 거극 부여 활성/초기화, 이름·스킬 필터, 선택 초기화, 실제 전체 규칙 세팅 검색 및 320·768·1440·1920px 가로 넘침 없음을 확인했다. 공개 사이트 배포는 실행하지 않았다.

2026-10-13 사용자 요청으로 탐색량을 200,000회에서 2,000,000회로, 시간을 20초에서 60초로 확대했다. 대표 결과 20개 제한과 워커 검색 취소는 유지한다. 시간에는 호석 후보 준비도 포함되며 횟수는 완성 세팅 수가 아닌 방어구/호석/장식주 계산 단계다.

호석 범위를 전체(규칙+제작) / 규칙만 / 제작만 / 보유만 / 없음으로 분리했다. 규칙만은 커뮤니티 생성 규칙, 제작만은 MHDB 고정 제작 목록을 사용한다. 보유 항목도 선택한 범위와 일치할 때만 대표 후보로 사용한다. 기존 자동 저장의 `all` 값은 전체 범위를 유지한다. 직접 세팅의 호석 목록은 제작/보유 optgroup으로 구분했다.

## 검색 결과 차이 요약

검색 결과 제목은 머리→상의→팔→허리→다리 순서의 방어구 이름 첫 글자와 α/β/γ 변형으로 구성한다. 첫 글자가 겹치는 서로 다른 이름은 두 번째 글자로 구분하고, 두 번째 글자도 충돌하면 두 글자를 사용한다. 같은 이름 계열의 부위·변형 차이는 충돌로 취급하지 않는다. 번호를 함께 표시하고 제목 툴팁·접근 가능한 이름·상세에서 전체 장비명을 확인한다. 기본 저장 이름도 같은 약어를 사용한다.

추가 스킬에는 목표에 없는 일반/시리즈/그룹 스킬과 목표 초과 레벨/단계를 표시한다. 일반 스킬은 무기·방어구·호석·장식주 합산 후 최대 레벨로 제한한다. 이번 결과들 사이에서 추가 레벨이 다르거나 일부 결과에만 있는 항목에는 금색과 ‘차이’ 문구를 함께 표시한다. 공통 추가 스킬도 표시하며 결과가 하나면 차이 표시를 붙이지 않는다.

호석은 종류·이름(기록된 경우)·스킬을 요약하며 미사용을 명시한다. 빈 슬롯은 실제 장식주 위치를 부위·종류·번호로 대조해 종류/크기별로 집계한다. 전체 합계(호석 포함)와 호석에 남은 슬롯을 별도로 표시한다. 검색 조건이나 계산 알고리즘은 변경하지 않는다.

검증: Node 65개 테스트 통과. Chromium 실제 호석 없음/제작 범위 검색에서 요약·차이 표시·키보드 펼침·기본 저장 이름과 저장 완료를 확인하고 320·768·1440·1920px 가로 넘침 없음을 확인했다.

사용자 지정 약어: 푸른빛무사=푸른, 퀸 전 부위=퀸, 이그졸스=이, 오메가=오. 본 시리즈도 부위명 대신 같은 시리즈 약어를 사용한다. 요청한 확인 목록은 레어도 6~8로 필터링하며 세팅 검색의 방어구 범위를 제한하는 변경은 아니다.

레다젤트=레, 다하딜라=다로 지정했다. 지정 약어를 우선하고 나머지 시리즈는 충돌 시 별도 약어로 구분한다. 전체 시리즈 약어의 중복 없음을 테스트한다. α/β/γ 모두 같은 시리즈 약어를 사용한다.

추가 지정 약어: 고그=그, 스컬페이스=스컬, 기운찬 모리바=모리바, 미러바이저=미러, 애널라이즈아이=애널라이즈, 오리온=오리온, 푸푸로페이크=푸푸로. 지정 약어를 우선하며 낮은 레어도의 그라비드 등은 별도 약어로 구분한다.

레어도 7 추가 지정 약어: 고어=고, 다마스크=다마, 도베르=도, 라기아=라, 라운드아이=라운드. 낮은 레어도의 발라는 라기아와 구분해 발라로 표시한다.

레어도 6 추가 지정 약어: 가쟈우=가쟈, 데스기어=데스, 귀신=귀신, 도샤구마=도샤, 레우스=레우, 모험의 호크하트=호크, 미츠네=미, 배틀=배틀, 봉인=봉인, 블랑고=블, 수호룡 세크레트=세크, 스퀘어글라스=스퀘, 실드=실드, 아즈즈=아즈즈, 아티어=아티어, 언더림글라스=언더.

앞 두 글자가 같지만 다른 시리즈인 길드에이스/길드크로스와 조사단/조사대는 별도로 구분한다. 기존 상위 약어를 유지해 길드에이스=길, 길드크로스=길크, 조사단=조, 조사대=조사대로 표시한다.

## 방어구 한계돌파

기존 MHDB의 `slots`는 기본 슬롯이며 한계돌파 후 슬롯 필드가 없다. [GameWith 한계돌파 가이드](https://gamewith.jp/mhwilds/536246)의 개별 방어구 슬롯 표 386개를 MHDB 일본어/한국어 공통 ID로 대조했다. 상위 레어도 5의 200개와 레어도 6의 186개를 모두 확인했고 이름과 기본 슬롯이 일치했다. 슬롯 표만 사실 데이터로 정리했으며 사이트 코드·이미지·원문 설명은 포함하지 않았다. 출처 URL·수집 시각·SHA-256은 `inputs/armor-limit-break-slots.json` 및 장비 스냅샷의 `armorLimitBreakSource`에 기록한다. 공식 게임 데이터 검증을 뜻하지 않는다.

일반적인 레어도 5의 세 슬롯/레어도 6의 왼쪽 두 슬롯 증가를 일괄 추정하지 않고 장비별 증가 슬롯을 `limitBreakSlots`로 기록했다. 예를 들어 호뢰악룡헬름β의 [2]는 [3,1], 미츠네그리브β의 [3]는 [3,1]로 변경된다. 체인헤드α는 가이드 개별 표의 [2,1,1]을 사용한다. 레어도 7·8과 하위 방어구는 슬롯을 변경하지 않는다. 내보내기 스크립트는 보완 표와 원본 이름·기본 슬롯이 다르면 중단하여 재검토를 요구한다.

세팅 검색 및 직접 세팅에 ‘한계돌파 슬롯 적용’ ON/OFF를 추가했고 기본값 및 초기화는 ON이다. 이전 자동 저장에 해당 필드가 없어도 ON으로 시작한다. 후보 축소·탐색·장식주 배치·슬롯 요약·상세·직접 선택 모두 적용한 슬롯을 사용한다. 직접 세팅에서 OFF로 전환하면 사라지거나 작아진 슬롯에 맞지 않는 장식주만 해제한다. on/off 입력을 자동 보관하며, 완성된 저장 세팅의 슬롯과 `armorLimitBreak` 값은 백업·복원·비교에도 보존한다. 기존 저장 세팅을 재계산하거나 바꾸지 않고 적용 상태 누락은 미기록으로 표시한다.

슬롯에 이어 한계돌파 후 최대 강화 방어력도 반영한다. 레어도 5/6/7/8의 일반 최대 강화 레벨 20/16/11/10과 한계돌파 최대 레벨 28/22/16/14를 [GameWith 강화 가이드](https://gamewith.jp/mhwilds/487360)에서 확인했다. 기존 MHDB의 기본/최대 방어력 차이가 모든 상위 장비에서 일반 최대 레벨×2와 일치함을 대조하고, 한계돌파 최대 방어력을 기본 방어력+최대 레벨×2로 기록했다. 부위당 증가량은 +16/+12/+10/+8이다. 실제 한계돌파 이후 최고 강화까지 완료한 상태로 계산하며 식사·스킬 보정은 포함하지 않는다. 스킬·내성·호석·무기 슬롯에는 한계돌파 보정을 적용하지 않는다.

검증: 전체 Node 테스트·Python 기존 테스트 및 내보내기 보완표 검증 통과. Chromium에서 기본 ON, 추가 슬롯, OFF 시 호환하지 않는 장식주 해제, ON/OFF 실제 검색, 저장/새로고침/복원/비교, 입력 자동 저장/초기화 ON과 320·768·1440px 가로 넘침 없음을 확인했다.

## 같은 방어구의 호석 후보 묶기

대표 결과 최대 20개는 서로 다른 방어구 다섯 부위 구성의 수다. 같은 구성의 호석 후보를 `charmVariants`에 묶고 후보별 장식주 배치·달성 스킬·발동 효과를 별도로 검증한다. 카드의 호석 선택을 바꾸면 요약/빈 슬롯/상세/저장 내용을 해당 후보로 갱신한다. 보유는 정규화한 스킬·레벨·종류별 슬롯의 정확 일치로 표시하며, 후보 목록과 요약에 표시한다. 동일 구성의 보유 기록 중복은 한 후보로 표시하며 보유 수량과 후보 수를 혼동하지 않는다.

미보유 호석은 기존 목표 기여 벡터·종류별 슬롯 구성이 같은 경우 대표로 합친다. 목표를 충족하는 다른 구성도 확인할 수 있도록 호석의 지배 관계 제거는 사용하지 않는다. 같은 목표/슬롯이어도 추가 스킬이 다른 보유 호석은 유지한다. 확인된 보유 후보를 먼저 확인·표시하며 미보유는 구성당 최대 200개 표시한다. 후보의 확인 수/보유 수/표시 제한을 명시한다. 호석 후보가 전체 게임 경우의 전수 목록이라는 뜻은 아니며 기존 60초/200만 단계에서 부분 검색으로 끝날 수 있다. 구성 20개 제한은 마지막 구성의 후보 확인을 마친 뒤 적용하며, 시간/탐색 제한이면 그 구성에서 이미 확인한 후보까지만 표시한다.

방어력 보완은 상위 582개에 적용한다. `baseDefense`와 `limitBreakDefense`를 포함하며 일반/한계돌파 방어력은 같은 on/off로 제어한다. 저장에는 슬롯 옵션 `armorLimitBreak`와 방어력 보완 상태 `armorLimitBreakDefense`를 기록한다. 과거 슬롯만 적용해 저장한 세팅은 그대로 보존하며 방어력 적용 상태가 없으면 ‘한계돌파 슬롯 ON’으로 표시한다.

검증: 전체 Node/Python 테스트와 582개 방어력 내보내기 정책 검증 통과. Chromium에서 실제 규칙/보유 검색의 20개 중복 없는 방어구 카드, 보유 우선 표시, 후보 전환 후 정확한 호석 저장, 한계돌파 방어력/직접 세팅/OFF/새로고침 및 320·768·1440px 가로 넘침 없음을 확인했다.

장비 상세의 최신 배치는 장식주 오른쪽에 호석을 표시하고, 오른쪽 열에 시리즈/그룹 스킬과 그 아래 방어 스테이터스를 배치한다. 검색 결과·직접 세팅·저장 상세에 같은 렌더러를 사용한다. 상세 반응형 규칙 및 검증은 UI-DESIGN-GUIDE.md를 참조한다.
