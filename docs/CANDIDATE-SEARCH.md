# 규칙 기준 호석 후보 검색

## 범위

전체 호석을 이용한 장비 세팅 검색의 첫 단계다. 사용자 제공 `inputs/호석테이블.xlsx`의 그룹·스킬 레벨·슬롯 조합에 출처가 있는 커뮤니티 보완 규칙을 적용해 검색한다. 실제 게임 전체 후보를 보장하거나 장비·장식주 세팅을 계산하는 기능은 아니다. 개인 추출 파일과 외부 시뮬레이터 코드는 배포하지 않는다.

## 데이터 조사

- 원본 SHA-256은 `prototype/data/talisman-recipes.json`에 기록한다.
- 조합 규칙 29개, 스킬 배정 633,379개, 슬롯 포함 단순 전개 2,134,102개다. 고유 호석 수나 출현 확률로 해석하지 않는다.
- 스킬 별칭은 기존 가져오기와 동일하게 정규화한다.
- W1은 무기 슬롯 크기 1, 숫자 슬롯은 방어구 슬롯, 0은 빈칸으로 해석한다. 이는 엑셀 해석이며 공식 생성 규칙 검증은 아니다.
- 같은 스킬명은 그룹·레벨에 관계없이 한 번만 배정하고 레벨을 합산하지 않는다. 커뮤니티 생성기와 계산기에서 교차 확인한 규칙이며 공식 명세는 아니다.
- 가드 강화 Lv.1은 그룹 1, Lv.2는 그룹 2·4, Lv.3은 그룹 3에 보완했다. 게임 추출 555행은 원본 엑셀에서 536행만 일치했으며 보완 후 555행 모두 일치했다. 이 결과는 해당 파일의 정확한 스킬·슬롯 구성 대조이며 게임 전체 후보나 실제 레어도를 증명하지 않는다. 개인 호석 구성은 문서나 배포 파일에 넣지 않았다. 출처와 상세 검토는 [TALISMAN-RULE-AUDIT.md](TALISMAN-RULE-AUDIT.md)를 따른다.
- 보완 후 스킬 배정 660,352개, 슬롯 포함 단순 전개 2,222,626개다. 출처와 보완 파일의 체크섬을 배포 JSON에 함께 기록한다.
- 원본 wiki-db 시뮬레이터 HTML과 검색 JS를 열람할 수 있었다. 검색 엔진·장비·장식주 데이터의 재사용 조건과 데이터 버전은 아직 확인하지 못했다. 그 코드를 앱에 가져오지 않았다.

## 기능과 화면 흐름

1. 메뉴의 **호석 후보 검색**을 연다. 와일즈 매뉴얼을 참고한 어두운 대화상자에서 범위를 안내한다.
2. 스킬 1~3개와 최소 레벨을 지정한다. 조건은 AND이며 스킬 1은 필수다. 레어도·최소 무기/방어구 슬롯·평가 무기·범용/무기별 평가로 추가 제한한다.
3. Web Worker에서 계산한다. 사용자는 검색을 취소하거나 창을 닫을 수 있다. 조건 수정은 실행 중 계산과 이전 결과를 취소한다.
4. 같은 스킬·레벨·슬롯 구성은 하나로 묶고 확인된 레어도와 엑셀 No를 모은다. 기존 태그 판정기를 적용하며 보유 수량은 구성 지문으로 비교한다. 후보를 자동으로 보유 호석에 등록하지 않는다.
5. 결과는 엑셀 행 순서로 최대 200개를 표시한다. 조건에 맞는 서로 다른 구성 20,000개를 넘으면 중단하고 **부분 검색**으로 명시한다. 이 경우 레어도/엑셀 No도 중단 시점까지 확인한 값이다.
6. 보유 데이터나 태그 기준이 바뀌면 결과를 무효화하고 다시 검색하도록 안내한다.

일치 후보가 없는 경우, 잘못된 스킬·중복 조건·잘못된 슬롯, 워커나 데이터 로딩 실패, 취소와 결과 제한을 구분한다. 검색은 HTTP(S) 실행이 필요하므로 GitHub Pages 사이트를 사용한다.

## 설계 검토 및 검증

- 목표 스킬이 해당 레시피의 어떤 그룹에서도 요구 레벨로 나타날 수 없을 때만 그 레시피를 건너뛴다. 슬롯 수와 크기는 종류별로 비교한다.
- 단위 테스트에서 별도의 완전 탐색과 결과를 대조한다. 중복 스킬 제외, 순서에 독립적인 지문, 레어도, 슬롯 종류/크기/개수, 스킬 레벨과 쿼리 검증을 확인한다.
- Chromium에서 실제 워커 검색, 정확 일치 태그, 보유 수량, 빈 결과·입력 오류·취소·조건 변경·데이터 버전 변경 무효화를 확인했다.
- 320·768·1440px에서 화면 넘침, 대화상자, Escape와 초점 복귀를 확인했다. 넓은 표는 표 영역 안에서 스크롤한다.
- 넓은 조건에서 20,000개 제한과 200개 표시, 부분 검색 문구를 확인했다.
- 기존 가져오기/태그 판정 테스트와 새 검색 테스트는 총 23개다.

## 다음 구현 전제

가드 강화 배정과 동일 스킬 중복 제외는 커뮤니티 근거를 기록해 반영했다. 공식 생성 규칙과 게임 버전 검증은 계속 추적한다. 장비·장식주·세트 효과 데이터를 버전과 함께 준비한 뒤, 목표 스킬에 필요한 잔여 조건으로 호석 후보를 줄이는 장비 세팅 검색 엔진을 구현한다. 제한 도달 결과를 전체 탐색 완료로 표시하지 않는 원칙을 유지한다.

## 재생성

`python scripts/export_talisman_recipes.py`로 원본 엑셀과 `inputs/talisman-rule-overrides.json`에서 배포용 JSON을 생성한다. Python `openpyxl`이 필요하며 앱 실행과 Node 테스트에는 필요하지 않다. 생성 파일의 체크섬·행 수·단순 전개 수를 테스트한다.
