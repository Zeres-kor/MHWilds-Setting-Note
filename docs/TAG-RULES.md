# 자동 태그 규칙과 업로드 양식 v1 초안

상태: 상세 설계와 화면 초안의 v1 판정 구현. 종결은 정확 일치, 준종결 이하 등급은 기준 이상 충족, 같은 범위는 최우선 태그 하나 표시로 합의했다. 이 문서는 호석의 실제 출현 가능성을 보증하지 않는다.

현재 화면은 2MB 이하 `.xlsx` 파일의 전체 교체/ID 병합, 오류 위치 표시, 기준 변경과 태그 변동 미리보기, 공통·무기별 판정, 기준·보유 목록의 함께 저장과 JSON 백업을 지원한다. 스킬명은 제공된 원본 호석 표의 112개 이름으로 검증한다. 생성 규칙을 통한 호석 가능 여부, 전체 검색 결과 분류, Windows 실기기 검증은 아직 연결되지 않았다.

## 합의한 기본 정책
- 평가 태그는 참고 HTML의 극종결, 종결, 준종결, 상급, 일반을 사용한다. 높은 순서로 극종결=1, 종결=2, 준종결=3, 상급=4, 일반=5를 양식 기본 순위로 둔다. 기준 범위마다 동일 순서를 사용한다.
- 극종결은 종결과 같은 정확 일치 방식으로 설계한다. 기존 HTML의 점수 등급 SSS/SS/S/A/B/C는 평가 태그와 별개이며 v1 자동 평가에 사용하지 않는다.
- 종결: 스킬판정=정확, 슬롯판정=정확. 추가 스킬·추가 슬롯·더 높은 레벨도 구성 차이가 있으면 해당 종결 기준에는 일치하지 않는다. 스킬·슬롯 입력 순서는 무시한다.
- 준종결 이하 등급: 스킬판정=이상, 슬롯판정=이상. 요구 스킬·슬롯을 충족하면 추가 스킬과 더 좋은 슬롯을 허용한다.
- 최우선 태그 하나를 범위별로 표시한다. 예: 범용 준종결과 태도 종결은 함께 표시되지만 태도 준종결은 함께 표시하지 않는다.
- 우선순위 숫자는 순위다. 작은 숫자가 우선이며 극종결=1, 종결=2, 준종결=3, 상급=4, 일반=5다.
- 규칙의 실제 비교 방식은 엑셀 열에 명시한다. 기본값과 다른 방식도 파일에 지정할 수 있으며 미리보기에서 표시한다.

## 1. 기준의 구조
한 행이 한 규칙이다. 행 안의 스킬과 슬롯 조건은 모두 충족해야 한다(AND). 같은 태그를 가진 여러 행 중 하나를 충족하면 해당 태그에 일치한다(OR). 적용무기가 공통인 행은 모든 무기에 적용하되, 태그 이름은 범용 범위로 구분해 표시한다. 무기별 행과 공통 행은 서로 덮어쓰지 않는다.

규칙 ID는 수정 전후 비교에 사용하는 고유 문자열이다. 태그명은 사용자가 정한다. 우선순위는 작은 숫자가 먼저다. 보유 여부·메모·수동 태그는 자동 판정 조건에 포함하지 않는다.

## 2. 엑셀 열
| 열 | 필수·허용 값 | 의미 |
|---|---|---|
| 기준ID | 필수, 파일 안에서 고유 | 예: COMMON-001 |
| 활성 | 필수, 예/아니오 | 비활성 행은 판정하지 않음 |
| 적용무기 | 필수 | 공통 또는 14종 무기 중 하나 |
| 태그 | 필수 | 극종결, 종결, 준종결, 상급, 일반 |
| 우선순위 | 필수, 1 이상의 정수 | 작은 숫자 우선 |
| 스킬판정 | 필수, 이상/정확 | 지정 스킬의 최소 조건 또는 전체 스킬 구성 일치 |
| 스킬1~3 / 레벨1~3 | 이름·레벨 쌍으로 입력 | 최대 3개, 레벨은 양의 정수 |
| 슬롯판정 | 필수, 이상/정확/무시 | 슬롯의 비교 방식 |
| 무기슬롯1~3 | 빈칸 또는 0~3 정수 | 규칙의 무기 슬롯 조건 |
| 방어구슬롯1~3 | 빈칸 또는 0~3 정수 | 규칙의 방어구 슬롯 조건 |
| 설명 | 선택 | 판정 근거에 함께 표시 |

레어도는 v1 태그 조건에 포함하지 않는다. 기존 TXT에는 레어도가 없어 스킬·슬롯으로 분류하는 편이 일관된다. 레어도 필터와 호석 생성 유효성은 별도 기능이다.

미분류는 평가 태그가 아니라 기준에 일치하지 않은 상태다. 불일치 호석을 자동으로 일반으로 간주하지 않는다. 일반도 업로드한 기준에 맞을 때 표시한다. 자유로운 메모·정리용 수동 태그는 평가 태그 목록과 별도로 관리한다.

## 3. 스킬 비교
- 스킬 순서는 무시하고 정규 스킬 ID로 비교한다.
- 이상: 지정된 각 스킬이 요구 레벨 이상이면 일치. 지정하지 않은 추가 스킬 허용.
- 정확: 스킬 집합과 각 레벨이 모두 같아야 일치. 추가 스킬은 불일치.
- 기준 행의 같은 스킬 중복 입력은 오류로 안내하고 한 칸에 정리하도록 한다.
- 보유 입력의 중복 스킬 합산·표기 처리는 게임 규칙 확인 전 확정하지 않는다.
- 스킬 조건 없는 행은 슬롯 조건만으로 판정할 수 있지만, 무조건 분류되는 행은 허용하지 않는다.

## 4. 슬롯 비교
무기와 방어구를 별도로 비교한다. 한 종류의 슬롯을 다른 종류의 슬롯 대신 쓸 수 없다. 0·빈칸은 슬롯 없음이다. 각 종류의 양수 슬롯을 내림차순 정렬한다.

- 이상: 실제 슬롯 수가 요구 수 이상이고, 각 위치의 실제 크기가 요구 크기 이상이어야 한다. 예: 요구 방어구 [2,1]은 실제 [3,1,1]과 일치하지만 [3]과는 불일치.
- 정확: 종류별 정렬된 양수 슬롯 배열이 완전히 같아야 한다. 추가 슬롯도 불일치.
- 무시: 슬롯을 평가하지 않는다. 혼동을 막기 위해 슬롯 값은 모두 비워야 한다.
- 이상에서 모든 슬롯이 0이면 슬롯 제한 없음. 정확에서 모두 0이면 슬롯 없는 호석만 일치.
- 양식의 0~3은 표현 범위다. 특정 무기 슬롯·호석 구성의 게임 내 가능 여부는 별도 생성 규칙으로 검증한다.

이 비교는 같은 종류에서 큰 슬롯이 작은 슬롯용 장식주를 수용한다는 게임 규칙을 확인한 뒤 적용한다. 세팅 검색은 장식주의 종류·실제 배치도 별도로 검증한다.

## 5. 겹치는 태그
범용과 선택 무기의 태그는 동시에 유지한다. 같은 범위에서는 가장 작은 우선순위의 일치 태그 하나만 표시하고 나머지 일치 근거는 상세에서 확인한다. 같은 범위·같은 우선순위에 서로 다른 활성 태그가 있으면 업로드 오류로 안내한다. 동률인 같은 태그의 규칙은 여러 근거로 허용한다.

## 6. 업로드와 적용
파일 검증 → 추가·변경·삭제 및 영향 미리보기 → 적용 순서. 미리보기 생성과 적용 사이에 기준 또는 호석이 변경됐으면 미리보기를 다시 계산한다. 적용 취소·검증 실패 시 기존 데이터는 유지한다.

업로드 모드 제안:
- 전체 교체: 파일의 규칙을 전체 기준으로 사용. 빠진 ID는 삭제된다. 미리보기에서 삭제 수를 명시한다.
- ID 병합: 기존 ID는 갱신, 새 ID는 추가, 파일에 없는 기존 ID는 유지한다. 병합으로 삭제하려면 활성=아니오로 비활성화하거나 전체 교체한다.

적용은 기준 버전과 재분류 결과를 함께 저장해 중간 상태가 보이지 않게 한다. 공통 기준 변경은 공통 분류를, 무기 기준 변경은 해당 무기의 분류를 갱신한다. 수동 태그·메모·보유 상태는 유지한다.

## 7. 오류와 안내
오류: 잘못된 헤더·무기명·스킬명, 중복 ID, 이름/레벨의 짝 누락, 잘못된 숫자, 중복 스킬, 충돌 우선순위, 아무 조건도 없는 규칙. 오류는 시트·행·열과 수정 방법을 표시한다. 빈 행은 무시한다. 비활성 예시도 형식 검사는 수행한다.

안내: 특정 규칙이 현재 보유 호석과 일치하지 않는 것은 오류가 아니다. 전체 생성 규칙에서 가능한지 검증하지 못한 경우에는 미검증으로 표시하고 불가능하다고 단정하지 않는다. 생성 규칙상 불가능하다고 검증된 활성 기준은 적용을 막고 근거를 표시한다. 매크로·수식 셀은 실행하거나 계산하지 않으며 기준 데이터 영역에 수식이 있으면 값 입력을 요구한다.

## 8. 예시 파일
templates/태그기준_빈양식.xlsx: 바로 입력할 수 있는 빈 양식.
templates/태그기준_작성예시.xlsx: 모두 비활성인 설명용 행. 종결 추천이나 게임 내 출현 가능성을 검증한 목록이 아니다.

예시 파일을 업로드할 때도 기준 미리보기와 적용 단계가 필요하며, 비활성 예시를 실제 판정에 사용하지 않는다.
