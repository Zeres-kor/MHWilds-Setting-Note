# 와일즈 세팅노트 PRD

상태: 합의 사항을 반영한 설계 초안. 구현 완료를 의미하지 않는다.

## 목적과 사용자
Windows PC에서 로컬로 실행하는 개인용 앱. 보유 호석을 빠르게 입력·관리하고, 생성 가능한 모든 랜덤 호석을 활용해 목표 스킬 세팅을 찾는다. 게임 데이터가 로컬에 준비되면 검색과 관리는 인터넷 연결 없이 가능해야 한다.

## 우선순위
1. 보유 호석 관리 자동화: 개별·일괄 입력, 정렬, 복합 필터, 일괄 작업, 자동 태그, 백업.
2. 엑셀 생성 규칙상 가능한 모든 랜덤 호석을 대상으로 세팅 검색.
3. 보유 호석만 대상으로 세팅 검색.

## 합의된 범위
- 화면은 창 너비를 활용하고 불필요한 좌우 여백을 줄인다.
- 필터·정렬·일괄 작업을 목록 가까이에 모은다.
- 자동 태그 기준은 보유 목록과 별도의 엑셀 파일로 수정한다.
- 평가 태그는 기존 HTML의 극종결 > 종결 > 준종결 > 상급 > 일반을 따른다. 극종결·종결은 정확 일치, 준종결 이하는 기준 이상이 기본이다. 미분류는 별도의 판정 상태다.
- 공통(모든 무기) 기준과 무기별 기준을 함께 적용한다.
- 동일 호석에 범용 준종결과 태도 종결이 동시에 붙을 수 있다.
- 보유 목록과 전체 가능 호석 검색에 같은 태그 판정기를 사용한다.
- 태그와 보유 여부는 독립적이다. 미보유 호석에도 태그를 표시한다.
- 기준 변경은 미리보기 후 적용하고 관련 자동 태그를 다시 계산한다.
- 빠른 개별 입력, 표 일괄 입력·붙여넣기, 기존 TXT 가져오기와 새 백업 형식을 지원한다.

## 모듈과 의존성
| ID | 책임 | 의존 |
|---|---|---|
| game-data | 스킬 ID, 슬롯 종류, 장비·장식주·세트 효과 | 없음 |
| talisman-rules | 엑셀 생성 규칙 해석과 호석 유효성 | game-data |
| tag-rules | 공통·무기별 기준 검증과 판정 | game-data |
| inventory | 보유 호석 입력·조회·저장·분류 | talisman-rules, tag-rules |
| solver | 전체/보유 호석 세팅 계산 | game-data, talisman-rules |
| search-ui | 검색 조건·결과·태그·보유 표시 | solver, inventory, tag-rules |
| saved-builds | 세팅 저장·조회 | search-ui |

구현 순서 제안: 데이터·규칙 확인 → 태그 판정과 보유 관리 → 전체 호석 검색 → 보유 호석 검색. 백업은 보유 관리와 함께 구현한다.

## 성공 기준
- 업로드 기준에 따라 동일 호석의 공통·무기별 태그가 일관되게 계산된다.
- 관리 화면과 검색 결과에서 같은 호석·같은 기준 버전은 같은 태그를 낸다.
- 전체 가능 호석 검색은 태그 기준이 없어도 동작한다.
- 검색 결과의 호석·장비·장식주 배치가 게임 규칙을 만족한다.
- 재분류는 수동 태그·메모를 보존한다.
- 백업·복원은 호석, 태그 기준, 수동 태그, 메모, 저장 세팅을 보존한다.
- 기준 업로드 실패 시 기존 기준·분류가 유지된다.
- 핵심 흐름은 Windows의 실제 브라우저에서 검증한다.

## 미확정 사항
- 지원할 게임 데이터 버전, 데이터 취득 방법·이용 조건.
- 동일 스킬 중복 배정과 합산, 슬롯 표기 해석 등 엑셀만으로 확정되지 않은 게임 규칙.
- 사용자 정의 태그의 기본 순위와 생성 규칙 확인에 따른 판정 세부 보완. 종결 정확 일치·준종결 이하 기준 이상·범위별 최우선 하나 표시는 확정했다.
- 붙여넣기 열 형식, 중복 호석의 수량 처리, 가져오기 충돌 정책.
- 실행 패키지 형태, 저장소 방식, 목표 PC에서의 성능 기준.

## 경계
캡처의 로그인·결제·서버는 일반 서비스 예시이며 현재 요구에 포함하지 않는다. 태그는 사용자 기준에 따른 분류로, 출현 확률 또는 세팅 전체의 성능을 뜻하지 않는다. 전체 호석 후보 수는 검증 전 단순 전개값과 유효 고유 호석 수를 구분한다.
