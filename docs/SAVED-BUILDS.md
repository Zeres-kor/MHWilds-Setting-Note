# 저장 세팅과 비교

세팅 검색 결과의 **이 세팅 저장**을 누르면 조합을 이 브라우저에 저장한다. **저장 세팅** (`#saved`) 페이지에서 이름·메모를 수정하거나 삭제하고, 최대 3개를 비교할 수 있다. 최대 저장 수는 200개다.

저장 항목은 검색 당시의 무기·방어구 이름과 슬롯, 호석 스킬·종류별 슬롯, 장식주 배치, 일반 스킬 총합(지원 최대 레벨로 제한), 목표 스킬, 발동 세트·그룹 효과, 최대 강화 방어력, MHDB 반영 버전과 호석 모드의 독립 스냅샷이다. 호석 목록을 나중에 수정하거나 삭제해도 스냅샷은 바뀌지 않는다. 현재 보유 여부나 최신 게임 규칙을 재검증하지 않는다.

비교 표는 선택된 조합의 모든 일반 스킬 이름을 합쳐 없는 스킬은 Lv.0으로 표시한다. 무기·각 방어구·호석·장식주 배치·발동 효과·방어력·목표·데이터 버전을 함께 비교하고 차이가 있는 행을 강조한다. 모바일은 표 안에서 좌우로 스크롤한다. 비교 선택 자체는 새로고침 후 초기화된다.

## 저장과 백업 호환

기존 `mhwilds-app-v2` 상태에 선택 필드 `savedBuilds`를 추가했다. 기존 저장에 해당 필드가 없으면 빈 목록으로 읽는다. 보유 호석·기준 변경은 저장 세팅을 보존한다. 저장 실패와 다른 탭의 변경은 기존 공통 저장 보호를 적용한다.

기존 `mhwilds-backup-v2` JSON 백업에 `savedBuilds`를 포함한다. 복원 확인에는 교체할 세팅 개수도 표시한다. 같은 v2의 예전 백업에 이 필드가 없으면 저장 세팅 0개로 교체한다. 가장 오래된 inventory 백업은 기존 기준과 저장 세팅을 유지한다. 복원은 전체 데이터 교체이므로 확인 전에 기존 백업을 저장할 수 있다.

복원 시 필드 길이와 수, ID 중복, 부위 누락, 목표 미달, 장식주 슬롯 종류·크기·중복 배치를 검증하고, 오류가 있으면 기존 전체 데이터를 유지한다. 이 형식 검증은 게임의 실제 가능성 검증이 아니다.

## 검증

단위 테스트는 실제 장비 검색 결과 스냅샷의 JSON 왕복·독립성, 손상된 슬롯 배치·누락 부위·중복 ID 등의 거부를 확인한다. Chromium에서 검색 결과 4개 저장, 이름·메모 수정, 3개 비교 제한·차이 표시, 삭제, 새로고침, 백업 다운로드·복원, 손상된 백업 거부, 이전 백업 호환 및 좁은 화면을 확인했다. Windows 실기기 검증은 별도 필요하다.

거극 아티어의 지정 시리즈·그룹 스킬은 선택 필드 `weaponBonuses`로 함께 보존하고 상세·비교에 각 1부위로 표시한다. 이전 저장/백업에 해당 필드가 없으면 빈 목록으로 읽는다.

기본 방어구의 불·물·번개·얼음·용 내성 합계와 검색 당시 최소 내성 조건을 저장한다. 이전 저장 세팅에 내성 값이 없으면 비교에서 미기록으로 표시하며 0으로 추정하지 않는다. 스킬·식사 효과는 내성 합계에 포함하지 않는다.

## 공통 상세 화면

검색 결과와 저장 세팅은 `BuildDetail`의 동일한 렌더러와 CSS를 사용한다. 저장 목록의 ‘장비·장식주 상세’를 열 때 공통 카드를 생성한다. 이후 상세 양식을 수정하면 두 화면에 함께 반영된다.

새 저장에는 선택 필드 `detail`로 레어도, 무기 종류, 장비 기본 스킬, 스킬 최대 레벨, 시리즈·그룹 단계와 기여 부위, 호석 규칙 레어도를 함께 보관한다. 기존 저장의 합계·장식주·발동 효과는 그대로 표시하며, 예전에 기록하지 않은 정보는 미기록으로 안내한다. 현재 장비 데이터로 과거 저장 내용을 재계산하지 않는다.

## 사용자 보관함

검색 결과 상세의 저장 양식에서 세팅 이름·보관함을 지정한다. 새 보관함 이름을 입력하면 세팅과 보관함을 함께 저장한다. 저장 세팅 페이지에서 전체/미분류/사용자 보관함으로 필터하고 빈 보관함도 만들 수 있다. 세팅마다 보관함 하나를 지정하며 이름·보관함·메모 저장으로 이동한다. 보관함 이름 변경은 소속을 유지하고, 보관함 삭제는 확인 후 세팅을 미분류로 옮긴다. 보관함은 최대 100개, 이름은 60자, 세팅 이름은 80자다.

동일 앱 상태 및 JSON 백업에 `savedFolders: [{id,name}]`와 각 세팅의 선택 필드 `folderId`를 저장한다. 빈 보관함도 백업한다. 보관함과 세팅을 한 번의 검증·쓰기 작업으로 변경하므로 저장 실패 시 부분 적용하지 않는다. 중복 보관함 ID/이름, 빈 이름, 존재하지 않는 보관함 소속은 거부한다. 이전 저장/백업에는 보관함이 없으며 세팅은 미분류로 표시한다. 이전 v2 백업 복원은 그 백업의 보관함 목록(없으면 빈 목록)으로 교체하고, 초기 호석 전용 백업은 기존 보관함과 저장 세팅을 유지한다.

Chromium에서 이름 지정 저장, 새 보관함 생성, 필터, 이동, 이름 변경, 새로고침 보존, 삭제 시 세팅 유지, JSON 다운로드·복원 및 320~1600px 화면을 검증했다.
